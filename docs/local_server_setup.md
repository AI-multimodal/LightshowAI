# Local Setup

This guide explains how to run the LightshowAI HTML page and XAS app locally in WSL before deploying.

## Overview

This local setup has two parts:

* **Apache** serves the static site from the repo’s `html/` folder.
* **XAS app** runs locally and is exposed through Apache at `/omnixas/`.

Expected flow:

1. Open `https://localhost/`
2. Apache serves `html/index.html`
3. That page contains an iframe pointing to `/omnixas/`
4. Apache proxies `/omnixas/` to the local XAS app

## Repo structure used by local setup

Important folders:

* `html/` — static site files
* `lightshowai/` — app code
* `deploy/apache/` — Apache config template
* `scripts/` — helper scripts
* `docs/` — documentation

Important files:

* `deploy/apache/lightshowai-local.conf.template`
* `scripts/setup-local-apache.sh`
* `scripts/run-xas-local.sh`
* `.env.example`
* `.env.local` (local only, do not commit)

## Prerequisites

This guide assumes:

* WSL Ubuntu
* the repo is already cloned locally
* you are using a Python environment such as conda

## Required environment variables

Create a local env file in the repo root:

```bash
cp .env.example .env.local
```

Set these variables in `.env.local`:

```dotenv
TILED_URL=...
TILED_API_KEY=...
XAS_SANDBOX_URL=...
```

Do not commit `.env.local`.

## One-time setup

### 1. Install Apache packages

```bash
sudo apt update
sudo apt install -y apache2 apache2-utils openssl
```

### 2. Enable required Apache modules

```bash
sudo a2enmod ssl
sudo a2enmod proxy
sudo a2enmod proxy_http
sudo a2enmod headers
```

These modules are needed for:

* HTTPS support
* reverse proxying `/omnixas/`
* setting response headers such as `X-Frame-Options`

### 3. Make scripts executable

From the repo root:

```bash
chmod +x scripts/run-xas-local.sh
chmod +x scripts/setup-local-apache.sh
```

### 4. Install project dependencies

Activate your conda environment first:

```bash
conda activate LightshowAI
```

Then install the project:

```bash
pip install -e .
```

### 5. Run Apache setup

From the repo root:

```bash
./scripts/setup-local-apache.sh
```

This script:

* creates local SSL certs
* creates Apache log folders
* renders the Apache config with your actual repo path
* installs the rendered config into Apache
* enables the site
* restarts Apache

## Starting the app

From the repo root:

```bash
conda activate LightshowAI
./scripts/run-xas-local.sh
```

Keep that terminal open while testing.

## Troubleshooting

### Apache warning: `APR_TCP_DEFER_ACCEPT`

If Apache restart shows a warning like this:

```text
AH00076: Failed to enable APR_TCP_DEFER_ACCEPT
```

this can be ignored in WSL for local development.

### Apache shows `Forbidden`

If you see:

```text
Forbidden
You don't have permission to access this resource.
```

Also make sure Apache can traverse the directories leading to the repo. Example:

```bash
chmod o+x /home/sairam
chmod o+x /home/sairam/LightshowAI
chmod o+x /home/sairam/LightshowAI/LightshowAI
chmod o+rx /home/sairam/LightshowAI/LightshowAI/html
chmod -R o+r /home/sairam/LightshowAI/LightshowAI/html
sudo service apache2 restart
```

Adjust the path to match your local username and repo location.

### Useful checks

Check Apache config syntax:

```bash
sudo apache2ctl configtest
```

Check Apache status:

```bash
sudo service apache2 status
```

Check Apache error log:

```bash
tail -n 50 .local/logs/apache2/error.log
```

Check URLs:

```bash
curl -k -I https://localhost/
curl -k -I https://localhost/omnixas/
```

## Notes

* The self-signed SSL certificate may trigger a browser warning. That is expected for local development.
* If the landing page loads but the iframe is blank, the issue is usually with the local app or the `/omnixas/` proxy target.
* If both `/` and `/omnixas/` fail with `Forbidden`, the issue is usually directory permissions.
